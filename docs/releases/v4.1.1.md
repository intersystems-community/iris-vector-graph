# v4.1.1 — 4.1.0 fixes

Body for the GitHub release page at
<https://github.com/intersystems-community/iris-vector-graph/releases/tag/v4.1.1>.
The page carries this text with the relative links below rewritten
to `blob/v4.1.1` URLs, since a release body does not resolve paths relative to this file.

---

A patch release. It fixes the five 4.1.0 bugs in DEBT entry 10 and the test gaps that
let them ship: among them a named-graph `delete_node` that returned `False`, fused
search lost on every 4.1.0 upgrade, and a wheel without the `Graph.KG` sources. It also works around three defects in the Arno callout that 4.1.0
shipped: PageRank, PPR, WCC, CDLP, subgraph and betweenness could return wrong
answers on Arno installs, and BFS raised on graphs over about 500 nodes.
`docker compose up` starts again.

## Install

```bash
pip install --upgrade iris-vector-graph==4.1.1
```

## Upgrading from 4.1.0

1. Run `initialize_schema()`. It now sends the `Graph.KG` classes from the wheel over
   the connection, so no `docker cp` is needed.
2. If 4.1.0's `upgrade_to_4_0_0` migrated the install, that same call restores
   `Graph_KG.kg_RRF_FUSE` (fused search failed with SQLCODE -30).
3. With `docker compose`: `docker compose down` first. The compose file now pins
   `containers.intersystems.com/intersystems/iris-community:2026.1`.

Behaviour changes to check:

- `delete_node` and `bulk_delete_nodes` take `graph=`. With none, they reach every
  graph holding the id, as in 4.1.0. A failed delete raises; `False` means only that
  there was no such node.
- On an Arno install, PageRank, PPR, WCC, CDLP, subgraph and global betweenness now
  come from ObjectScript. Scores can differ from 4.1.0's; 4.1.0's were wrong (see
  [KNOWN_ISSUES § Arno callout defects](../KNOWN_ISSUES.md)). `direction="both"`
  betweenness is undirected (LazyKG).
- `fhir_graph_sync` replies `"rebuilt": "repository_behind_watermark"` when the
  repository was reset or restored under the graph.
- iris-devtester 1.20 no longer creates the `test`/`test` user.

The full list is in [CHANGELOG.md](../../CHANGELOG.md).
